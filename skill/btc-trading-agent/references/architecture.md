# 架构说明

## 为什么分成 Agent 层和代码层

交易系统需要两类完全不同的能力：

**A. 需要浏览器 + 语义理解**
- CoinGlass 清算地图（API 加密，只能浏览器看）
- CoinGlass 多空比、Whale bias
- 推特情绪（需登录、有反爬）
- 金十快讯 + 判断"美联储鹰派暂停意味着什么"

**B. 需要确定性和毫秒级**
- 算仓位（风险预算反推）
- 下单、挂条件单、对账
- 每分钟扫信号

**没有 Agent**：A 类数据拿不到，只能编模型 → 输出假数据。
**没有代码**：B 类算不准，且 LLM 不可能 24 小时每分钟醒着。

## 数据流

```
浏览器（Agent）                     代码（每 60 秒）
     │                                   │
     ├─ CoinGlass 清算 ──→ data/coinglass.json ──┐
     ├─ 推特分层     ──→ data/x_posts.json    ──┤
     │                                          ├→ scoring.build()
     ├─ OKX 强平流 ─────────────────────────────┤   （五层汇总）
     ├─ FRED/新浪/Yahoo ────────────────────────┤        │
     ├─ 金十快讯 ───────────────────────────────┤        ↓
     └─ 新闻 RSS + LLM 分类 ────────────────────┘   strategy.detect()
                                                          │
                                                          ↓
                                                    risk.finalize()
                                                          │
                                                          ↓
                                            executor（下单/止损/记账）
```

## 五层评分

| 层 | 范围 | 内容 |
|---|---|---|
| L1 宏观 | -9 ~ +9 | CPI/通胀动能/能源/油价/纳指VIX/美元/2Y/溢价/地缘 |
| L2 资金 | -3 ~ +3 | 清算燃料比 R + 持仓拥挤度（散户/大户/费率/鲸鱼） |
| L3 技术 | -3 ~ +3 | 4h+1h 均线/MACD/结构；日线独立计分 |
| L4 事件 | -2 ~ +2 | 新闻情绪 + 突发检测 + 日历扣分 |
| L5 风控 | 一票否决 | 止损位置/强平缓冲/保证金上限/风险预算/日亏熔断 |

**方向推导**：
```
bias      = 由 L1 + L4 决定
direction = L2 在"区间"状态下可以翻转 bias
```

## 四个入场模型

| 模型 | 触发条件 | 方向 |
|---|---|---|
| A 阻力回抽 | 价格冲到关键位 + 拒绝形态（长上影/收在下沿） | 空 |
| B 支撑回踩 | 价格跌到关键位 + 支撑形态 | 多 |
| C 假跌破 | 跌破支撑后快速收回 | 多 |
| D 假突破 | 突破阻力后快速跌回 | 空 |

四个模型**全部评估**，取置信度最高的。逆势不再被禁止，而是被减仓。

## 仓位计算链

```
止损距离 → 钳制到 [1.2%, 2.0%]
         ↓
保证金% = 风险预算(5%) ÷ (杠杆10 × 止损%)
         ↓  受 margin_pct(33%) 上限约束
保证金USD = 权益 × 保证金%
         ↓
张数 = 保证金 × 杠杆 ÷ 价格 ÷ ctVal(0.01)
         ↓
再乘 size_mult（逆势 0.33 / 逆日线 0.5 / 逆L2 0.5 / 连亏 0.5）
```

## 双向持仓的实现要点

1. OKX 必须切到 `long_short_mode`（**有持仓时不能切**，需先清仓）
2. 所有订单必须带 `posSide`（`long` / `short`），否则拒单
3. **`pos` 永远是正数**，方向只能看 `posSide` —— 早期代码用正负号判断，把空单认成多单，导致裸空
4. 本地状态用 `positions: {"long": Position, "short": Position}`
